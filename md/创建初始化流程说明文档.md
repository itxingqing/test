## 步骤2：初始化密钥 ⭐

### 2.1 什么是"初始化"？

**初始化 = 生成唯一的密钥对和盐值**

这个步骤会生成以下三个关键数据：

| 数据 | 用途 | 存储位置 | 是否保密 |
|------|------|---------|---------|
| RSA私钥 | 服务器签名令牌 | 服务器application.yml | ✅ 绝密 |
| RSA公钥 | 客户端验证签名 | 客户端代码 | ❌ 公开 |
| HKDF盐值 | 增强密钥派生安全性 | 服务器application.yml | ✅ 绝密 |

### 2.2 为什么需要初始化？

❌ **错误做法**：直接使用示例代码中的密钥
- 所有人的服务器都用相同密钥
- 极易被破解和伪造
- 无安全性可言

✅ **正确做法**：每个部署生成唯一密钥
- 你的服务器有独特的密钥对
- 攻击者无法伪造你的签名
- 保证系统安全性

### 2.3 执行初始化

**在服务器项目目录下执行：**

```bash
# 1. 进入服务器项目
cd /path/to/license-server

# 2. 编译项目
mvn clean compile

# 3. 运行密钥生成工具
mvn exec:java -Dexec.mainClass="com.yourcompany.license.util.KeyGenerator"
```

### 2.4 保存输出结果

工具会输出类似以下内容：

```
================================================================================
步骤 3/3：配置说明

服务器端配置
--------------------------------------------------------------------------------
license:
  server:
    private-key: MIIEvQIBADANBgkqhkiG9w0BAQEFAASCBKcw...（很长的Base64字符串）
    hkdf-salt: qP2xF7N8k3L9m4R5s6T7u8V9w0X1y2Z3A4B5...（很长的Base64字符串）

客户端配置
--------------------------------------------------------------------------------
公钥（Base64格式）：
MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8AMIIB...（很长的Base64字符串）
```

**⚠️ 立即保存这些内容！**

建议保存到：
1. **密码管理器**（如1Password、LastPass）
2. **加密文件**（使用VeraCrypt等工具）
3. **离线存储**（USB加密盘）

**❌ 不要保存到：**
- Git仓库
- 未加密的文本文件
- 邮件或聊天记录
- 云同步文件夹（如Dropbox）

### 2.5 初始化只需要执行一次

```
首次部署 → 运行KeyGenerator → 保存密钥 → 完成 ✅

后续部署 → 使用已保存的密钥 → 无需重新生成 ✅

密钥丢失 → 需要重新生成 → 所有客户端需重新激活 ⚠️
```

## 步骤3：配置服务器

### 3.1 配置数据库

```bash
# 登录MySQL
mysql -u root -p

# 创建数据库
CREATE DATABASE license_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

# 导入表结构
USE license_db;
SOURCE /path/to/database-schema.sql;

# 验证表创建成功
SHOW TABLES;
# 应该看到：licenses, activations, heartbeat_logs
```

### 3.2 配置密钥（开发环境）

编辑 `src/main/resources/application.yml`：

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/license_db?useSSL=false&serverTimezone=UTC
    username: root
    password: your_mysql_password

license:
  server:
    # ⭐ 粘贴KeyGenerator输出的完整私钥（一整行，不要换行）
    private-key: MIIEvQIBADANBgkqhkiG9w0BAQEFAASCBKcw...
    
    # ⭐ 粘贴KeyGenerator输出的完整盐值（一整行，不要换行）
    hkdf-salt: qP2xF7N8k3L9m4R5s6T7u8V9w0X1y2Z3A4B5...
```

### 3.3 配置密钥（生产环境，推荐）

**方式1：使用环境变量**

```bash
# 在服务器上设置环境变量
export LICENSE_SERVER_PRIVATE_KEY="MIIEvQIBADANBgkqhkiG9w0BAQEFAASC..."
export LICENSE_SERVER_SALT="qP2xF7N8k3L9m4R5s6T7u8V9w0X1y2Z3..."

# 将这些命令添加到 ~/.bashrc 或 /etc/profile
```

然后 `application.yml` 使用引用：

```yaml
license:
  server:
    private-key: ${LICENSE_SERVER_PRIVATE_KEY}
    hkdf-salt: ${LICENSE_SERVER_SALT}
```

**方式2：使用配置管理工具**

- Spring Cloud Config Server
- HashiCorp Vault
- AWS Secrets Manager
- Azure Key Vault

### 3.4 启动并验证

```bash
# 启动服务器
mvn spring-boot:run

# 查看启动日志，应该看到：
# ✅ 许可证服务初始化完成

# 测试健康检查
curl http://localhost:8080/api/v2/health
# 应该返回：OK
```

**常见错误：**

| 错误信息 | 原因 | 解决方法 |
|---------|------|---------|
| `HKDF盐值长度必须为64字节` | 盐值配置错误 | 检查是否完整复制了Base64字符串 |
| `初始化HKDF盐值失败` | 盐值格式错误 | 确保没有多余的空格或换行 |
| `无法加载私钥` | 私钥配置错误 | 检查私钥的Base64格式 |

## 步骤4：配置客户端

### 4.1 转换公钥格式

**为什么需要转换？**
- Java生成的公钥是X509 SubjectPublicKeyInfo格式（Base64）
- C#需要RSAKeyValue格式（XML）
- 需要使用转换工具

**执行转换：**

```bash
# 方式1：使用C#转换工具
cd client
dotnet run --project PublicKeyConverter

# 粘贴KeyGenerator输出的公钥Base64字符串
# 工具会输出XML格式
```

**输出示例：**

```xml
<RSAKeyValue>
  <Modulus>xK7L9m4R5s6T7u8V9w0X1y2Z3A4B5C6D7E8F9G0H...</Modulus>
  <Exponent>AQAB</Exponent>
</RSAKeyValue>
```

### 4.2 配置公钥到客户端

编辑 `CryptoHelper.cs`：

```csharp
// ⭐ 将上面转换得到的XML格式公钥粘贴到这里
private const string SERVER_PUBLIC_KEY = @"
<RSAKeyValue>
  <Modulus>xK7L9m4R5s6T7u8V9w0X1y2Z3A4B5C6D7E8F9G0H...</Modulus>
  <Exponent>AQAB</Exponent>
</RSAKeyValue>";
```

### 4.3 配置服务器地址

编辑 `LicenseManager.cs`：

```csharp
// 开发环境
private const string SERVER_URL = "http://localhost:8080";

// 生产环境
private const string SERVER_URL = "https://license.yourcompany.com";
```

## 🔧 常见问题排查

### Q1: 启动时报"HKDF盐值未初始化"

**原因：** CryptoUtil未正确读取配置

**解决：**
1. 检查 `application.yml` 中 `license.server.hkdf-salt` 是否配置
2. 检查盐值是否为完整的Base64字符串（应该很长）
3. 重启服务器

### Q2: 客户端激活时报"令牌签名验证失败"

**原因：** 服务器公钥配置错误

**解决：**
1. 重新运行 `PublicKeyConverter` 转换公钥
2. 确保XML格式完整，包含 `<Modulus>` 和 `<Exponent>`
3. 重新编译客户端

### Q3: 配置了密钥但服务器仍然报错

**检查清单：**
```bash
# 1. 验证配置文件语法
cat src/main/resources/application.yml | grep "private-key"

# 2. 验证密钥长度
# 私钥Base64长度应该约1700个字符
# 盐值Base64长度应该约88个字符

# 3. 检查是否有多余的空格或换行
```

## 🎓 关键概念总结

### 密钥的生命周期

```
生成（初始化） → 配置 → 使用 → 备份 → 轮换（可选）
   ↓               ↓      ↓       ↓        ↓
一次性操作      部署时   运行时  定期    年度或泄漏时
```

### 密钥的存储位置

| 密钥类型 | 服务器 | 客户端 | 配置文件 | 环境变量 |
|---------|--------|--------|---------|---------|
| RSA私钥 | ✅ | ❌ | ⚠️ 可以 | ✅ 推荐 |
| RSA公钥 | ❌ | ✅ | ✅ | ❌ |
| HKDF盐值 | ✅ | ❌ | ⚠️ 可以 | ✅ 推荐 |

### 什么时候需要重新初始化？

**需要：**
- ✅ 首次部署新服务器
- ✅ 密钥泄露或怀疑泄露
- ✅ 安全策略要求定期轮换（如每年）
- ✅ 迁移到新的服务器集群

**不需要：**
- ❌ 服务器重启
- ❌ 更新代码
- ❌ 数据库迁移
- ❌ 客户端更新
